# 毛发渲染库（fur-render）设计方案

> 状态：**待评审**。本文只描述设计，不含实现。
> 定位：独立库，用**真实发丝几何**渲染猫毛；`cat-house` 以静态库方式引用。
> 结论先行：**不做贴图伪造、不做壳层为主方案**，一期即生成真实发丝并实例化绘制。

---

## 〇、决策摘要（评审重点）

| # | 决策 | 建议值 |
|---|---|---|
| 1 | 几何形态 | 发丝 Ribbon，每段一个面向相机的四边形，实例化绘制 |
| 2 | 几何预算 | **段预算制**：中档 ≤ 48 万段（= 6 万根 × 8 段），参数超限自动钳制 |
| 3 | 生成位置 | 一期 CPU 生成（可复现、易调试）；别名表 O(1) 采样 + 一次性预分配，生成过程零 `malloc` |
| 4 | 透明处理 | 4x MSAA + alpha-to-coverage + 段级深度偏移，不做排序 |
| 5 | 光照 | Kajiya-Kay 漫反射 + 双层高光 + 发根 AO + 发尖提亮 |
| 6 | 与贴图关系 | 发根颜色从烘焙后的 baseColor 贴图按 UV 采样，花色自动继承 |
| 7 | 动画 | 一期静态；接口预留骨骼，等资产权重修复后再接 |
| 8 | 降级 | 只做「档位降发丝量」，壳层降级路径不进一期（见附录 A） |
| 9 | 第三方依赖 | **只用算法，不引毛发库**；运行期仅依赖已引入的 `glad` + `cglm` |
| 10 | 性能策略 | 预算制 + 单 draw call + 距离 LOD 一期即有；F1 就出性能基线，不留到 F4 |

## 〇.1 性能前置约束

性能从数据结构与接口阶段锁定，不等实现完再优化。

**目标预算（1280×800，目标机实测后校准）**

| 指标 | 上限 |
|---|---|
| 毛发 GPU 时间 | ≤ 3.0 ms/帧 |
| 段实例数 | ≤ 48 万（中档） |
| 段数据显存 | ≤ 20 MB |
| 生成耗时（一次性） | ≤ 80 ms |
| Draw call | 1 |
| CPU 提交 | ≤ 0.2 ms |

**六条硬约束**

1. **段预算制代替根数制**：`strand_count` 只是派生值，真正的上限是 `strand_count × segment_count ≤ 段预算`。任何表型组合超限都被钳制，接口层保证不会炸显存。
2. **单 draw call + 紧凑实例**：每段 36 字节，整只猫一次 `glDrawElementsInstanced`；不做逐根 VBO、不做逐根 draw。
3. **不排序**：A2C + MSAA + 段级深度偏移，省掉 O(n log n) 排序与额外 RT。
4. **一期就有距离 LOD**：发丝生成时按随机优先级排序，LOD 只改 `instance_count` 前缀（见 6.6），不重建几何。
5. **生成侧零分配**：三角形面积前缀和做别名表，采样 O(1)；所有缓冲一次性预分配，生成过程无 `malloc`。
6. **内建计时**：库自己统计生成耗时与 GPU 耗时，`fur_get_stats` 返回；F1 即可出基线，不依赖外部 profiler。

## 一、目标与非目标

### 目标

- **真实发丝**：每根毛有长度、粗细、弯曲，可透视、剪影可见、可逐根受光。
- **独立成库**：`third-lib/fur-render/`，一个头文件 + 一个静态库，宿主只调用、不碰内部。
- **资产复用**：直接吃 `Model` 的网格与烘焙后贴图，不要求新资产格式。
- **表型驱动**：毛长、毛质（正常/卷毛/无毛）决定发丝数量、长度、卷曲。
- **可复现**：同一 `(网格, 参数, seed)` 生成结果逐字节一致。
- **可分级**：三档质量，帧率可控。

### 非目标

- 毛发动力学（碰撞、梳理、风力模拟）。
- 离线级多次散射。
- GPU 骨骼蒙皮（`cat.glb` 的 `JOINTS_0` 全 0、权重恒为 `(1,0,0,0)`，见 `doc/texbake-对接说明.md` §6.3）。
- 毛发建模工具、美术摆片、发片贴图生产。
- 除 baseColor 外的材质通道。

## 二、为什么必须用真实发丝

| 手段 | 剪影 | 透视 | 单根高光 | 近景可信度 |
|---|---|---|---|---|
| 贴图 + 法线扰动 | 完全平滑 | 无 | 无 | 低：看起来像「毛绒贴纸」 |
| 壳层 Shell | 仍平滑（层叠面） | 仅层间镂空 | 弱 | 中：中远景可用，特写露馅 |
| **发丝 Ribbon** | 边缘出毛 | 每根独立 | 有（Kajiya-Kay） | 高 |

你的要求是「真实毛发、不仅仅是贴图」，因此唯一能满足的是发丝几何。壳层只保留为弱机降级选项，不作为主方案。

## 三、总体架构

```
cat-house（宿主）
  gene_lib_phenotype
        │  hair_length / hair_texture
        ▼
  FurParams ──────────────┐
  Model（网格 + 烘焙贴图） ─┤ FurMeshDesc（裸数组视图）
        │                  ▼
        │            fur-render 库
        │              ├─ 发根采样（面积加权 + 重心坐标）
        │              ├─ 取色（UV 采样烘焙贴图）
        │              ├─ 生长（重力 / 卷曲 / 成束）
        │              ├─ 打包段实例 → VBO（一次）
        │              └─ 实例化绘制（顶点着色器展开 Ribbon）
        ▼                  ▼
  renderer_draw_model   共用同一深度缓冲
```

边界：

- 库**只画毛发**，不画身体、不碰相机、不碰 UI、不写 UI。
- 库不依赖 `model.h`，用裸数组视图接收数据，因此可以独立复用与单测。
- 库依赖 `glad`（函数指针）与 `cglm`（数学），与 `model-making`（纯 CPU）分层。

## 四、对外接口规格

### 4.1 头文件

```c
/* fur.h —— 唯一对外头文件 */
#define FUR_API_VERSION 1

typedef enum {
    FUR_OK = 0,
    FUR_ERR_NULL = -1,
    FUR_ERR_GL = -2,
    FUR_ERR_OOM = -3,
    FUR_ERR_INVALID_ARG = -4,
} FurStatus;

/* 网格视图：裸数组，不依赖宿主类型 */
typedef struct {
    const float    *positions;      /* 3 * vertex_count */
    const float    *normals;        /* 3 * vertex_count */
    const float    *uvs;            /* 2 * vertex_count */
    const uint32_t *indices;        /* 3 * index_count */
    uint32_t vertex_count;
    uint32_t index_count;

    const uint8_t  *basecolor_rgba; /* 烘焙后贴图，行优先，原点左上 */
    int basecolor_width;
    int basecolor_height;
} FurMeshDesc;

typedef struct {
    int      strand_count;   /* 0 = 由 density 推导 */
    int      segment_count;  /* 4..16，默认 8 */
    float    length;         /* 毛长，对象空间单位 */
    float    density;        /* 0..1 */
    float    width;          /* 发根半径，对象空间单位 */
    float    tip_scale;      /* 发尖半径比例，0..1 */
    float    gravity;        /* 下垂强度 */
    float    clumping;       /* 成束强度 0..1 */
    float    frizz;          /* 毛躁 / 卷曲 0..1 */
    float    root_ao;        /* 根部遮蔽 0..1 */
    float    tip_lightening; /* 发尖提亮 0..1 */
    uint32_t seed;           /* 可复现 */
} FurParams;

typedef struct {
    float direction[3];      /* 与身体材质共用同一方向光 */
    float color[3];
    float ambient[3];
} FurLighting;

typedef struct {
    int strand_count;
    int segment_count;
    int instance_count;      /* strand_count * segment_count */
    int vertex_bytes;        /* 段实例数据占用 */
    float generate_ms;       /* 最近一次 fur_set_mesh 的 CPU 耗时 */
    float gpu_ms;            /* 上一帧 fur_draw 的 GPU 耗时 */
} FurStats;

typedef struct FurContext FurContext;

int  fur_get_api_version(void);
int  fur_create(FurContext **out);          /* 需 GL 上下文 + glad 已加载 */
void fur_destroy(FurContext *fur);

int  fur_set_mesh(FurContext *fur, const FurMeshDesc *mesh, const FurParams *params);
void fur_set_params(FurContext *fur, const FurParams *params);
void fur_set_lighting(FurContext *fur, const FurLighting *lighting);
void fur_get_stats(const FurContext *fur, FurStats *stats);

void fur_draw(const FurContext *fur,
              const float model[16], const float view[16], const float proj[16],
              const float camera_pos[3]);
```

### 4.2 生命周期与契约

| 项 | 约定 |
|---|---|
| 初始化顺序 | `SDL_GL_CreateContext` → `gladLoadGLLoader` → `fur_create` |
| 线程 | 全部接口单线程调用，且调用线程必须持有当前 GL 上下文 |
| 内存 | `FurMeshDesc` 内指针仅在 `fur_set_mesh` 调用期间有效，库内部自行复制 |
| GL 状态 | `fur_draw` 进入时保存、退出时恢复它改动的状态（深度、混合、剔除、程序、VAO） |
| 绘制目标 | 使用调用方当前绑定的 framebuffer 与深度缓冲，不改视口 |
| 销毁 | `fur_destroy` 需在同一上下文内调用 |
| 错误 | 全部返回 `FurStatus`；`fur_draw` 无返回值，失败状态在 `fur_get_stats` 中体现 |

### 4.3 宿主侧调用示例

```c
/* 初始化：窗口 + GL 就绪之后 */
FurContext *fur = NULL;
fur_create(&fur);

/* 重随机时：Model 还活着的时候交出视图 */
FurMeshDesc desc = {
    .positions = (const float *)model.vertices,   /* 需按实际布局取址 */
    .normals   = ...,
    .uvs       = ...,
    .indices   = model.primitives[0].indices,
    .vertex_count = model.primitives[0].vertex_count,
    .index_count  = model.primitives[0].index_count,
    .basecolor_rgba = model.textures[0].pixels,
    .basecolor_width  = model.textures[0].width,
    .basecolor_height = model.textures[0].height,
};

FurParams params = {0};
params.segment_count = 8;
params.length  = phenotype.hair_length == GENE_LIB_HAIR_LONG ? 0.22f : 0.12f;
params.density = 0.55f;
params.seed    = 12345u;
fur_set_mesh(fur, &desc, &params);

/* 每帧：身体之后 */
renderer_draw_model(&renderer, &gpu, tint);
fur_draw(fur, model_matrix, view, projection, eye);
```

> `ModelVertex` 是 `position/normal/uv` 紧凑结构，宿主需按字段取址或先拆成三条数组；具体形式在实现阶段确定，接口不变。

## 五、发丝生成

### 5.1 流程

1. **三角形面积前缀和 → 别名表**，O(1) 采样到三角形 → 重心坐标随机取点 → 插值出位置、法线、UV。
2. **取色**：用 UV 对烘焙贴图双线性采样，得到该根发丝的颜色。
3. **初始朝向**：`normalize(normal * 0.75 + tangent * 0.25)`，`tangent` 由对象空间 3D 噪声给出。
4. **成束**：根点量化到簇，同簇发丝向簇心偏移，强度由 `clumping` 控制。
5. **逐段生长**：见 5.2。
6. **打包实例**：每段一条记录，写进预分配好的 VBO（不做逐根分配）。

生成开始前先算段预算：`strand_count = min(用户请求, 段预算 / segment_count)`，再按表面积与 `density` 修正。

> 噪声用**对象空间**而非 UV：`cat.glb` 的 UV atlas 有 1653 个岛、覆盖率约 60%，UV 噪声在岛边界必然断裂。这与 `texbake` 改表面烘焙是同一个原因。

### 5.2 单段推进

```
t    = i / segment_count
dir  = normalize(dir_prev + gravity·(0,-1,0)·dt + curlNoise·frizz)
pos  = pos_prev + dir · (length / segment_count)
r    = width · mix(1, tip_scale, t)
ao   = mix(1, 1 - root_ao, smoothstep(0, 0.35, t))
col  = mix(rootColor, rootColor·(1 + tip_lightening), t)
```

`curlNoise` = 对象空间 3D 噪声 + 正弦叠加；`frizz` 同时提高频率与幅度（rex 卷毛靠它）。

### 5.3 参数默认值

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `strand_count` | 0（自动） | 0 / 10k~200k | 0 时由 `density` 与表面积推导，最终受段预算钳制 |
| `segment_count` | 8 | 4~16 | 越高越顺滑，成本线性上升 |
| `length` | 0.12 | 0.02~0.35 | 对象空间单位（模型最长轴半长为 1） |
| `density` | 0.55 | 0~1 | 覆盖率 |
| `width` | 0.0015 | 0.0005~0.004 | 发根半径 |
| `tip_scale` | 0.25 | 0~1 | 发尖收细 |
| `gravity` | 0.25 | 0~1 | 下垂 |
| `clumping` | 0.45 | 0~1 | 成束 |
| `frizz` | 0.25 | 0~1 | 毛躁 |
| `root_ao` | 0.6 | 0~1 | 根部压暗 |
| `tip_lightening` | 0.2 | 0~1 | 发尖提亮 |

### 5.4 噪声

自研 3D 值噪声（value noise + 平滑插值），不引入外部噪声库，也不用 UV：

- 低频层（频率 1~3）：决定毛流方向，保证相邻发根大体同向。
- 高频层（频率 8~20）：`frizz` 的逐段抖动，卷毛猫主要靠它。
- 置换表由 `seed` 生成（256 项），保证同一只猫可复现。
- 成本：每段约 2 次采样，中档 6 万 × 8 段 = 96 万次，一次性生成可接受。

### 5.5 可复现与缓存

- 随机流由 `seed` 派生；同一只猫每次生成一致。
- 生成结果可序列化为 `.furbin`：`版本号 + 参数哈希 + 网格哈希 + 段数组`。
- 一期可选不做缓存；若实测启动阻塞明显，再加缓存。缓存缺失或哈希不符时静默重新生成。

## 六、渲染实现

### 6.1 段实例数据布局（每段 36 字节）

| 字段 | 类型 | 字节 | 说明 |
|---|---|---|---|
| `origin` | vec3 | 12 | 段起点，对象空间 |
| `offset` | vec3 | 12 | 段位移（长度 + 方向），`dir = normalize(offset)` |
| `width` | float | 4 | 段半径 |
| `color` | RGBA8 | 4 | 发根颜色 |
| `aux` | 4×uint8 | 4 | `t`、`ao`、每根随机相位、保留 |

显存（估算）：6 万根 × 8 段 = 48 万段 ≈ 17MB；12 万根 × 10 段 ≈ 43MB。

### 6.2 顶点展开

每个实例画 4 顶点 / 6 索引，一次 `glDrawElementsInstanced`：

```glsl
vec3 dir   = normalize(offset);
vec3 view  = normalize(camera_pos - origin);
vec3 side  = normalize(cross(dir, view));
vec3 pos   = origin + offset * cornerY + side * width * cornerX;
```

- `cornerX ∈ {-1, +1}`、`cornerY ∈ {0, 1}`，由 `gl_VertexID` 查常量表得到。
- 相邻段在屏幕空间留 0.5px 重叠，避免断裂。
- 不背面剔除；按视线方向翻转切线，保证背面有光。

### 6.3 透明与深度

不排序，采用覆盖率近似：

1. 身体网格先画（不透明、写深度）。
2. 毛发开 `GL_SAMPLE_ALPHA_TO_COVERAGE`，4x MSAA，深度测试与写入均开启。
3. 每段按 `t` 施加微小深度偏移（根在前、尖在后），避免同根自穿插。
4. alpha 低于覆盖阈值的片元被采样丢弃，无需按距离排序。

前提：宿主窗口必须开 4x MSAA：

```c
SDL_GL_SetAttribute(SDL_GL_MULTISAMPLEBUFFERS, 1);
SDL_GL_SetAttribute(SDL_GL_MULTISAMPLESAMPLES, 4);
```

若仍出现明显穿帮，再加毛发深度预通道；OIT 不进一期。

### 6.4 光照

- Kajiya-Kay：切线取段方向，`sin(T,L)` 漫反射。
- 双层高光：主高光偏移小、次高光偏移大（模拟毛鳞片）。
- 环境光复用场景值；发根 AO 压暗；发尖提亮。
- 与身体材质共用同一个 `direction / color / ambient`，避免两张皮。

### 6.5 抗锯齿

- 屏幕空间宽度 < 1.5px 时按比例衰减 alpha，抑制亚像素闪烁。
- 发尖 alpha 渐隐，避免硬切。
- 依赖 MSAA + A2C；TAA 属于后处理，不在库范围。

### 6.6 距离 LOD

- 生成时按 `seed` 打乱发丝顺序，使**任意前缀都是均匀随机子集**；段数据按「发丝优先」连续存放。
- 按模型包围球的屏幕投影高度分档：`> 35%` 全量，`12%~35%` 画前 50%，`< 12%` 画前 25%。
- LOD 只改 `instance_count`，不重建 VBO、不换 shader、不额外 draw call。
- 档位切换带 2% 滞回，避免相机移动时来回跳。
- 远景同时加大亚像素 alpha 衰减，进一步压 overdraw。

## 七、表型映射

| 表型 | 映射 |
|---|---|
| `HAIR_TEXTURE_HAIRLESS` | `strand_count = 0`，不建几何、不绘制 |
| `HAIR_TEXTURE_REX` | `length × 0.5`、`frizz = 0.8`、`clumping = 0.2` |
| `HAIR_TEXTURE_NORMAL` | 默认值 |
| `HAIR_SHORT` | `length` 取默认、`gravity` 小 |
| `HAIR_LONG` | `length × 1.8`、`gravity` 大、档位提一档 |
| 花色 / 白斑 / 重点色 | 无需处理：发根颜色采样烘焙贴图，自动继承 |

副作用提醒：`texbake` 的贴图必须保留明暗细节（`detail_strength` 不要设 0），否则毛发会显得平。

## 八、性能验证与调优

`cat.glb` 约 1.8 万三角形。档位定义如下，上限见 〇.1：

| 档位 | 发丝数 | 段数 | 段实例 | 三角形 | 段数据显存 |
|---|---|---|---|---|---|
| 高 | 120,000 | 10 | 1,200,000 | 2.4M | ~43MB |
| 中（默认） | 60,000 | 8 | 480,000 | 960K | ~17MB |
| 低 | 25,000 | 6 | 150,000 | 300K | ~5.4MB |

**测量方法**

- GPU：`GL_TIME_ELAPSED` 查询包住整个毛发 pass，结果写入 `FurStats.gpu_ms`。
- CPU：`fur_set_mesh` 前后计时，写入 `FurStats.generate_ms`。
- 帧级：RenderDoc 抓一帧，核对 draw call 数、实例数、overdraw 热区。

**调优顺序**（先改画质参数，最后才降几何）

1. 提高亚像素 alpha 衰减阈值，减少远景无效片元。
2. 降低 `width` 与 `tip_scale`，减少覆盖面积。
3. 降 LOD 档位（改 `instance_count`）。
4. 最后才降 `segment_count`（会牺牲顺滑度）。

主要开销始终是片元 overdraw，不在顶点端；48 万段的顶点处理在目标机上不是瓶颈。

## 十一、验收标准

### F1 几何正确

- 发根贴合表面，无可见悬浮或穿模（近景截图）。
- 发丝剪影可见，单根可分辨。
- 一次 draw call；切换开关前后，身体渲染结果不变。
- **同时产出性能基线**：`generate_ms`、`gpu_ms`、`instance_count` 三个数值记录在案，与 〇.1 预算对照。

### F2 外观正确

- 发根颜色与烘焙贴图对应 UV 的采样值一致（抽样比对）。
- 花色、白斑、重点色在毛发上正确出现。
- 旋转相机一周，无大面积闪烁、无明显排序穿帮。

### F3 表型正确

- 无毛猫：`strand_count = 0`，渲染结果与关闭毛发一致。
- 长毛/卷毛：长度与弯曲肉眼可区分。

### F4 性能达标

- 中档（6 万 × 8 段）在目标机 1280×800 稳定 60fps，毛发 pass 的 `gpu_ms ≤ 3.0`。
- 三档切换后帧率变化符合线性预期。
- 显存占用与第八章档位表偏差不超过 20%，且不突破 〇.1 的上限。

## 十二、风险与规避

| 风险 | 规避 |
|---|---|
| 半透明排序穿帮 | A2C + 4x MSAA + 段级深度偏移；仍不行加深度预通道 |
| 发丝过多掉帧 | 三档质量；后续再做按屏幕占比动态降档 |
| 生成阻塞启动 | 实测；必要时 `.furbin` 缓存或异步生成 |
| 发根浮空 | 根点沿法线内缩极小量；对象空间定义与 `texbake` 保持一致 |
| 亚像素频闪 | 宽度 < 1.5px 时 alpha 衰减 |
| 蒙皮退化无法动画 | 一期静态；接口预留骨骼，资产修复后接入 |
| 与身体光照不一致 | 库不引入独立光照模型，只接受宿主传入参数 |
| 破坏宿主 GL 状态 | 进入保存 / 退出恢复；只用自有 VAO 与程序 |
| 贴图缺少细节导致毛发扁平 | 约定 `detail_strength ≥ 0.8` |

## 十三、待确认事项

1. **画质倾向**：写实（多层高光、透光感）还是偏二次元（硬边色阶）？
2. **默认档位**：6 万根 × 8 段是否可接受？是否要冲 12 万根？
3. **分布策略**：全身均匀，还是按部位差异化（头/尾/腹不同密度与长度）？
4. **生成位置**：一期 CPU（建议）还是直接 compute shader？
5. **缓存**：允许在运行目录写 `.furbin` 吗？
6. **MSAA**：是否接受窗口固定 4x MSAA？不可则降级为抖动 alpha，画质降一档。
7. **降级**：弱机是否需要自动退回壳层（附录 A，需要额外实现）？

## 十四、第三方依赖取舍

**结论：需要「成熟算法」，不需要「成熟库」。** 现有毛发实现要么绑定 D3D/引擎，要么自带一整套模拟与排序管线，移植到 OpenGL 4.5 + C 的成本高于自研核心。

### 14.1 候选评估

| 候选 | 类型 | 许可 | 后端 | 结论 |
|---|---|---|---|---|
| AMD TressFX（GPUOpen） | 完整毛发系统：模拟 + PPLL + LOD + 渲染 | 开源（以仓库 LICENSE 为准） | D3D12 / Vulkan | 不采用：后端不匹配，且大部分模块（碰撞、模拟、排序）一期不需要 |
| NVIDIA HairWorks | 商业中间件 | 商业授权 | D3D11 / D3D12 | 不采用：闭源、无 OpenGL |
| Unreal Hair Strands / Unity 毛发 | 引擎内功能 | 引擎许可 | 引擎 | 不采用：无法独立抽出 |
| Cem Yuksel Hair Meshes 等研究代码 | 参考实现 | 学术代码 | 旧 GL / D3D | 只借鉴算法 |
| three.js / Babylon.js 毛发示例 | WebGL 实现 | MIT | WebGL | 只借鉴着色器结构 |

共同问题：这些实现把「毛发生成 + 透明排序 + 光照 + 模拟」打包成一个整体，接入即意味着接受它的 GL 抽象层与数据布局，与本项目「管线自持、库只做一件事」的边界冲突。

### 14.2 建议借鉴的算法（只读资料，不引代码）

| 资料 | 用途 |
|---|---|
| Kajiya & Kay 1989 | 各向异性高光，第六章光照的基准 |
| Marschner 2003 | R / TT / TRT 散射模型，实时版可简化为主 + 次高光 |
| Scheuermann GDC 2004 | Ribbon 展开与 alpha 处理，6.2 / 6.3 的依据 |
| UE4/UE5 Hair Shading | 双高光参数与深度偏移的工程取值 |
| TressFX 论文与文档 | PPLL、LOD、模拟，作为二期升级参考 |

### 14.3 运行期依赖

| 依赖 | 用途 | 状态 |
|---|---|---|
| glad | GL 函数加载 | 已引入 |
| cglm | 矩阵 / 向量 | 已引入 |
| 自研 3D 值噪声 | 毛流 / 卷曲 / 成束扰动 | 库内实现（约几十行），见 5.4，不新增依赖 |
| stb_image_write | 调试导出（毛发遮罩、截图） | 仅调试用，可选 |
| RenderDoc | 帧调试 | 工具，非运行期依赖 |

除上表外，**不新增任何第三方库**。

### 14.4 明确不引入

- 物理引擎（Bullet / PhysX）：一期不做毛发动力学。
- 大型 C++ 数学库（Eigen / glm）：与 C 项目不匹配。
- 引擎级渲染框架（bgfx / Filament）：会把现有 `renderer` 架空。

## 附录 A：可选降级路径（不进一期）

若确认需要低端机兜底，可在同一 `FurContext` 内部增加 `mode = SHELL`：

- 复用现有网格，沿法线复制 24~32 层，采样同一张烘焙贴图，alpha 由 `density` 控制。
- 绘制成本远低于发丝，但剪影与特写质量下降。
- 对外接口不变，仅增加 `fur_set_quality()` 的一个枚举值。

该路径只在确认「必须支持弱机」时实施，避免一期范围膨胀。
