# 渲染主程序架构（修订版）

> 定位：本项目**负责渲染管线与 glb 模型加载**。基因、族谱、贴图烘焙由其他项目实现，以预编译库的形式放入 `third-lib` 引入。
> 当前目标：把「窗口 → 相机 → 着色器 → 绘制」管线搭好，并跑通「随机基因 → 表型 → 烘焙贴图 → 加载模型 → 渲染」全链路。
> 现状：全链路已跑通，视图中渲染一只猫；界面左上角 `REROLL` 按钮（或 `R` 键）重新随机基因并重烘、重载、重绘。

## 一、职责边界

**本项目（cat-house）负责：**

- 一个普通 3D 场景窗口：相机、光照、清屏与交换
- 渲染管线：GL 状态、着色器、材质与网格绘制
- glb → CPU 侧 `Model` 的加载（`src/model.c`，基于 cgltf + stb_image）
- 表型 → 烘焙指令的翻译（`src/appearance.c`，`GeneLibPhenotype` → `TexbakePattern`）
- 表型 → 模型资产变体的选择（`src/cat_asset.c`，命名约定 + 逐级回退）
- 叠加层 UI（自绘按钮与文字，`src/ui.c`）

**本项目不负责：**

- 花纹贴图的绘制算法与 glb 写回 —— `third-lib/model-making/`（`texbake_bake_glb_surface`）
- 基因生成 / 繁育算法 —— `third-lib/gene-lib/`
- 族谱、亲属关系、猫咪登记 —— `third-lib/relationship/`
- 行为状态机、存档节奏等业务规则
- ECS 框架（Flecs 暂不引入）

**数据单向流动**：逻辑库 → 渲染层。渲染层只读，不修改基因与族谱。

## 二、依赖

### 2.1 已接入的第三方逻辑库（`third-lib/`）

| 库 | CMake 目标 | 提供的接口 |
|---|---|---|
| `libgene-lib.a` + `gene_lib.h` | `gene_lib` | `gene_lib_seed/generate`（随机生成）、`gene_lib_breed`（繁育）、`gene_lib_describe`（文本描述）、`gene_lib_phenotype`（机器可读表型） |
| `librelationship.a` + `relationship.h` | `relationship` | `Pedigree / Litter / Cat` 数据结构，`cat_add / cat_children / cat_ancestors / cat_generation_all` 等查询，`pedigree_save / load` |
| `libmodelmaking.a` + `texbake.h` | `model_making` | `texbake_render_surface`（3D 求值预览）、`texbake_bake_glb_surface`（表面烘焙：3D 图层逐 UV 纹素求值 + gutter 膨胀，写回新 glb 的 baseColorTexture） |
| `libfurrender.a` + `fur.h` | `fur_render` | `fur_create / destroy`、`fur_set_mesh`（网格 + 烘焙贴图 + 参数）、`fur_set_lighting`、`fur_get_stats`、`fur_draw`（真实发丝 Ribbon，alpha-to-coverage + 距离 LOD） |

约定：`GeneLibGene.value` 是**不透明基因载体**，渲染层不解析其位含义，只通过 `gene_lib_phenotype` 取表型。
`gene_lib` 内部持有全局随机流，必须单线程串行调用。

### 2.2 渲染相关依赖

| 库 | 作用 |
|---|---|
| SDL2 | 窗口、事件、OpenGL 上下文 |
| glad | OpenGL 4.5 core 函数加载 |
| cglm | 矩阵 / 向量 / 四元数 |
| cgltf | glb / glTF 解析（`src/model.c`） |
| stb | `stb_image` 解码内嵌贴图、`stb_easy_font` 生成 UI 文字 |
| fur-render | 真实发丝毛发（`lib/libfurrender.a` + `include/fur.h`）；库自行 `LoadLibraryA`/`GetProcAddress` 加载 GL 函数，宿主无需暴露 glad 符号 |

模型加载约定：`model.h` 是**纯 CPU 数据契约**（顶点 / 索引 / RGBA 像素 / 绘制项 / 包围球），不出现任何图形 API 类型，可脱离窗口做单测；GPU 上传与绘制由本项目 `renderer` 负责。
贴图烘焙由 `model_making` 完成，它只替换 glb 里的 baseColorTexture，不产出 `Model`；本项目的 `model_load` 负责把烘焙后的 glb 读成 `Model`。
烘焙一律走**表面烘焙**（`texbake_bake_glb_surface`）：图案在归一化对象空间求值，跨 UV 岛连续，不受 atlas 碎片化影响。

### 2.3 目录与构建

```
cat-house/
├─ include/       本项目对外头文件（model.h / renderer.h / appearance.h / cat_asset.h / ui.h）
├─ src/           渲染主程序（入口 main.c、model.c、appearance.c、cat_asset.c、ui.c） → bin/cat-house.exe
├─ assets/        原始资产（cat.glb，可扩展 cat_<tag>.glb 变体）
├─ test/          CuTest 单元测试入口               → bin/cat-house-test.exe
├─ third-lib/     第三方库，一个库一个目录
└─ doc/           设计文档
```

`third-lib/` 内每个库自成一目录，目录内统一为 `include/`（头文件）、`src/`（需编译的源码）、`lib/`（预编译库）、`CMakeLists.txt`：

```
third-lib/
├─ sdl2/          源码编译静态库（与主程序同一套 UCRT 运行时）
├─ glad/          glad.c → glad      （OpenGL 4.5 core）
├─ cglm/          header-only        （cglm     INTERFACE 目标）
├─ cgltf/         cgltf.h + src/cgltf_impl.c                    （cgltf）
├─ stb/           stb_image.h / stb_easy_font.h + src/*_impl.c  （stb）
├─ gene-lib/      lib/libgene-lib.a + include/gene_lib.h        （gene_lib）
├─ relationship/  lib/librelationship.a + include/relationship.h（relationship）
├─ model-making/  lib/libmodelmaking.a + include/texbake.h      （model_making）
└─ fur-render/    lib/libfurrender.a + include/fur.h            （fur_render）
```

- `third-lib/CMakeLists.txt` 只负责 `add_subdirectory` 各库；预编译库用 `add_library(... STATIC IMPORTED GLOBAL)` 暴露 `gene_lib`、`relationship`、`model_making`、`fur_render`。
- `src` 产出可执行程序，链接 `gene_lib`、`relationship`、`model_making`、`fur_render`、`cgltf`、`stb`、SDL2、glad、cglm；`-Wall -Wextra` 只作用于本项目代码。
- `test` 直接编译 `src/*.c`（排除 `main.c`）并链接同一批库，无需额外造库。
- Windows 下主程序定义 `SDL_MAIN_HANDLED` 并自带 `main`，不依赖 `SDL2main`。

## 三、核心数据流

```
gene_lib_seed / gene_lib_generate（流浪猫）
gene_lib_breed（亲代 → 子代）        ──► GeneLibGene { value }
                                              │
                                              ├─► gene_lib_describe()  ──► 文本（控制台 / 窗口标题）
                                              │
relationship：pedigree_init / cat_add / cat_litters … ──► Cat { litter, gene }
                                              │
                                        gene_lib_phenotype()
                                              ▼
                                     GeneLibPhenotype
                                              ├─ cat_asset_select()（本项目）──► assets/cat_<tag>....glb
                                              │  appearance_build_pattern()（本项目）
                                              ▼
                        TexbakePattern（BLOB3D / STRIPE3D / GRADIENT3D / NOISE3D）
                                              │  texbake_bake_glb_surface()（model-making）
                                              ▼
                    选中的变体 glb ──► cat_baked.glb（内嵌新 baseColorTexture）
                                              │  model_load()（本项目，cgltf + stb）
                                              ▼
                                      Model（纯 CPU：网格 + RGBA 贴图 + 绘制项）
                                              │  renderer_upload_model()
                                              ▼
                                        GpuModel  ──► renderer_draw_model
                                              │  merged_mesh_build()（本项目）
                                              ▼
                         对象空间合并网格 + 烘焙贴图 ──► fur_set_mesh（fur-render）
                                              ▼
                                        fur_draw（身体之后绘制）
```

一次重随机（`REROLL` 按钮 / `R` 键）完整走一遍：`gene_lib_generate` → `gene_lib_phenotype` → `cat_asset_select` → `appearance_build_pattern` → `texbake_bake_glb_surface` → `model_load` → `renderer_upload_model` → `fur_set_mesh`，随后销毁旧的 `GpuModel`。毛发参数（长度 / 粗细 / 密度 / 卷曲）由表型映射，并按合并网格的包围盒高度标定。

渲染层每只猫只需要三样输入：

1. 烘焙后的资产（`Model`：网格、贴图、绘制项）
2. 变换（位置、朝向、缩放）；二期再补充动画状态（动画名、播放进度、混合权重）
3. 实例着色参数（如整体色调），可选

## 四、表型 → 外观映射（本项目翻译字段，model-making 负责绘制）

> `src/appearance.c` 只做字段翻译：`GeneLibPhenotype` → `TexbakePattern`（颜色查调色板、图层类型与参数映射）。
> 基因库给的是 UV 空间指令，烘焙库的表面 API 只接受 3D 图元，翻译后的对应关系：
> `REGION → BLOB3D`（按部位锚定椭球）、`STRIPE → STRIPE3D`（曲线数量 → period/width，沿身体前后轴）、
> `GRADIENT → GRADIENT3D`（param → strength，沿身体轴）、`NOISE → NOISE3D`（count → frequency，表型派生 seed）。
> 真正的贴图绘制与 glb 写回在 `model-making` 的 `texbake_bake_glb_surface` 内；本项目不实现绘制算法。

| 表型字段 | 渲染用途 |
|---|---|
| `sex` / `alive` | 体型比例微调；`alive == 0` 不生成实例 |
| `base_color` | 调色板索引 → albedo 基色 |
| `orange / agouti / pattern / brown / dilution / silver / colorpoint / white` | 决定最终毛色与是否存在花纹，是 `pattern_layout` 的成因，渲染层只消费结果 |
| `pattern_layout` | 花纹指令：元球区域（白斑/玳瑁）、贝塞尔条纹（虎斑）、渐变（重点色）、噪声（银化/烟色）。按 `layers[0..count-1]` 顺序叠加；翻译时换成 3D 图元（BLOB3D / STRIPE3D / GRADIENT3D / NOISE3D），在对象空间求值 |
| `ear_shape` + `ear_severity` | 立耳/折耳/卷耳：耳朵骨骼旋转 + 顶点混合权重 |
| `eye_color` | 眼部材质参数 |
| `hair_length` / `hair_texture` | 毛发参数：`hair_length` 长毛 → 长度 ×1.8 且加大下垂；`hair_texture` 卷毛 → 长度减半、提高卷曲，无毛 → 不生成发丝 |
| `leg_length` | 腿骨缩放（矮脚） |
| `tail_form` | 尾骨长度/形态 |

一期落地范围：已消费 `base_color`、`pattern_layout`、`hair_length`、`hair_texture`；`eye_color` 可选；`ear_shape / leg_length / tail_form` 等骨骼类字段先解析、不呈现，等二期模型与骨骼完善后再接入。

实现优先级建议：

1. 先做 `base_color` 调色板 + `pattern_layout` 烘焙到一张花纹贴图（CPU 生成 → 上传 GPU）；
2. 静态白模阶段不做形态变化；需要区分品种时，最多做整体缩放，不碰骨骼；
3. `eye_color` 用材质参数近似；`hair_*` 已通过 fur-render 接入。

## 五、渲染子系统

| 模块 | 职责 | 归属 |
|---|---|---|
| 平台层 | SDL2 窗口/事件、OpenGL 上下文 | 本项目 |
| 绘制层 | 透视相机、深度测试、着色器、方向光、材质与网格绘制 | 本项目 |
| 场景层 | 轨道相机、清屏与交换、单只猫展示 | 本项目 |
| 资产加载 | glb 解析、节点世界矩阵、内嵌贴图解码 → `Model` | 本项目（cgltf + stb） |
| 表现层 | 表型 → `TexbakePattern`（3D 图元）翻译；`texbake_bake_glb_surface` 表面烘焙出新 glb | 本项目翻译 + model-making 烘焙 |
| 毛发层 | 合并网格 + 烘焙贴图 → 发丝几何；与身体共用光照、深度缓冲；`F` 键开关 | fur-render |
| 叠加层 UI | 自绘按钮与文字（stb_easy_font 四边形） | 本项目 |
| 骨骼动画（二期） | 动画采样、蒙皮矩阵 | 待定 |

关键简化：场景很小、模型数量有限，一期只有静态姿势；不做阴影、后处理、视锥剔除与 LOD，也不需要动画状态机。

## 六、资产规范

- 模型（一期）：glTF 2.0 Binary `.glb`，**静态站立的猫咪网格即可**，不要求骨骼与动画；
- 动画（二期）：全部放在同一 glb，骨架唯一，名称固定 `idle / sleep / pet / walk`，骨骼命名不使用中文；
- 贴图：PNG，sRGB；眼睛与花纹可用 Alpha；
- 配置：`cat_asset_config.json`，记录资产路径、默认材质、光照、各动画速度、动画混合时长；
- 坐标：统一 Y-up（Blender 导出时设置），C 侧不做多套坐标转换。

模型接入：原始资产放 `assets/cat.glb`，运行时烘焙产物写 `cat_baked.glb`（已在 `.gitignore` 中忽略）；换模型只替换 `assets/` 下的资产，不改管线接口。

形态变体由独立模块 [src/cat_asset.c](src/cat_asset.c) 负责（表头见 `include/cat_asset.h`）：`cat.glb` 的蒙皮是退化的（`JOINTS_0` 全 0、权重恒为 `(1,0,0,0)`），无法靠骨骼形变，只能切换不同的 GLB 资产。

命名约定：`assets/cat<_tag>_<tag>....glb`，**只写偏离默认值的性状**，所以普通猫仍是 `assets/cat.glb`。

| 性状 | 默认值 | 非默认片段 |
|---|---|---|
| `ear_shape` | straight | `ear-fold` / `ear-curl` |
| `hair_texture` | normal | `fur-rex` / `fur-hairless` |
| `hair_length` | short | `fur-long` |
| `leg_length` | normal | `leg-short` / `leg-severe` |
| `tail_form` | long | `tail-short` / `tail-bob` |

选择流程：`cat_asset_traits()` 按优先级收集片段（耳形 > 毛质 > 毛长 > 腿长 > 尾形），`cat_asset_select()` 从完整组合开始、每次裁掉优先级最低的一项再试，全部未命中则回落到 `assets/cat.glb`。扩展新性状只需在 `cat_asset.c` 的 `RULES` 表加一条取值函数（数组位置即优先级），路径拼接与回退逻辑不变。

可选：Godot 4 仅作为**离线**资产校验/调参工具（检查骨骼权重、动画断裂、材质参数），产出的参数写进 json；它不参与打包，也不承担任何运行期逻辑。

## 七、里程碑

### M1：基因接入（已完成）

- `test/` 调用 `gene_lib_seed` + `gene_lib_generate`，并校验 `gene_lib_describe` 能产出非空文本；
- `src/main.c` 启动时生成一份基因并打印描述文本。

### M2：窗口 + 空场景（已完成）

- SDL2 + glad 建窗口与 OpenGL 4.5 上下文；
- 透视相机、固定方向光、深度测试、清屏与交换；
- 不加载任何模型；模型库接入后在这里调用 `renderer_upload_model` 并挂上 `GpuModel`。

### M3：模型加载 + 静态展示（已完成）

- `src/model.c` 实现 `model_load / model_free`：cgltf 解析 glb、按节点世界矩阵生成绘制项、stb_image 解码内嵌贴图、计算包围球；
- 主程序用 `renderer_upload_model` 上传为 `GpuModel`，交给 `renderer_draw_model` 绘制，相机按半径自动取景。

### M4：表型驱动外观（已完成）

- `src/appearance.c` 把 `GeneLibPhenotype` 翻译成 `TexbakePattern`（3D 图元）；
- 主程序随机生成基因 → `texbake_bake_glb_surface` 表面烘焙 `cat_baked.glb` → `model_load` → 上传绘制；
- 界面 `REROLL` 按钮 / `R` 键重新随机基因，重烘、重载、重绘；窗口标题显示基因描述。

### M4.5：真实毛发（已完成）

- `third-lib/fur-render` 以预编译静态库接入，`fur_create` 在 GL 上下文之后创建；
- 主程序把 `Model` 的全部绘制项按节点世界矩阵合并成一份对象空间网格，连同烘焙贴图交给 `fur_set_mesh`；
- 表型映射毛长 / 毛质 → `length / gravity / frizz / density`，并按网格高度标定尺度；无毛猫不生成发丝；
- 毛流统一沿 `-Z`（鼻尖 → 尾），配合低 `lift` 让短毛贴体顺滑，避免「炸毛」；
- 按 UV 光栅化生成 `fur_mask_rgba`：头顶短绒、五官区无毛，其余部位正常毛长；
- 窗口以 4x MSAA + alpha-to-coverage 渲染发丝，`F` 键开关；每帧在身体之后 `fur_draw`。

### M5：多实例 + 族链接入

- 从 `Pedigree` 遍历 `Cat`，`gene → phenotype → 实例`；
- 实例化绘制，验证几十只猫的帧率；
- 用 `cat_generation_all` 生成代际信息，控制台展示。

### M6：场景展示与打包

- 多只猫在场景中摆放、相机可调；
- 静态链接、资产目录打包。

### 二期：动画与形态

- 骨骼动画采样、蒙皮、动画混合（`idle / sleep / pet / walk`）；
- `ear_shape / leg_length / tail_form / hair_*` 的形态表现；
- 与游戏逻辑库对接行为状态机；
- 一期所有代码按「资产句柄 + 表型」抽象，二期只补渲染管线，不改调用方。

## 八、风险与规避

| 风险 | 规避 |
|---|---|
| 一期把模型/动画耦合进渲染流程 | 一期只做静态网格；动画相关代码（采样、蒙皮、状态机）全部留到二期，调用方只认资产句柄 |
| 白模内容与预期不符（比例、朝向、材质槽） | 白模到位后先跑 M2 单只验证；比例、朝向、材质槽位写进 `cat_asset_config.json` |
| 表型字段语义理解偏差 | 以 `gene_lib.h` 注释为准；表现层只消费字段，不反推基因位点 |
| 实例多时性能下降 | 材质相同的猫合并批次，实例化绘制；花纹贴图按表型缓存（相同表型共享） |
| （二期）骨骼矩阵写错导致模型扭曲 | 先用 Godot/RenderDoc 对照；把骨骼矩阵写日志比对 |
| （二期）模型库动画插值与引擎不一致 | 以 Godot 播放结果为真值，先实现 linear，再补 step/cubic |

## 九、暂缓 / 后续

- **Flecs ECS：暂不引入**。当前猫的数量与系统复杂度用 `Pedigree` + 简单数组即可；若后续出现大量系统编排需求再评估。
- **游戏逻辑库**：未来以静态库形式加入 `third-lib`，与渲染层约定只读快照接口：`(gene, transform, 动画状态, 资产 id)`。
- **存档**：直接复用 `pedigree_save / pedigree_load`，渲染层不参与序列化。
- **基因反查**：渲染层不解析 `GeneLibGene.value`；需要更多外观细节时，优先推动 gene_lib 增加表型字段。
