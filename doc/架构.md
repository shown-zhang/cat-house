# 渲染主程序架构（修订版）

> 定位：本项目**只负责渲染**。基因、族谱、行为等游戏逻辑由其他项目实现，以库的形式放入 `third-lib` 引入。
> 当前目标：用 `gene_lib` 生成一份基因 → 解释成表型（phenotype）→ 渲染层按表型把猫画出来。
> 现状：白模只有**静态站立**版本，一期不接入动画与蒙皮；当前重点是打通「基因 → 表型 → 渲染」全流程，模型本身不是重点。

## 一、职责边界

**本项目（cat-house）负责：**

- 一个普通 3D 场景窗口：相机、光照、模型摆放与绘制
- glTF 静态网格加载与绘制（骨骼动画、蒙皮放到二期）
- 按表型（`GeneLibPhenotype`）决定外观：毛色、花纹、耳型、腿长、尾型、眼睛、毛发质感
- 多实例绘制、调试面板（Dear ImGui）

**本项目不负责：**

- 基因生成 / 繁育算法 —— `third-lib/gene_lib.h`
- 族谱、亲属关系、猫咪登记 —— `third-lib/relationship.h`
- 行为状态机、存档节奏等业务规则 —— 后续由游戏逻辑库提供
- ECS 框架（Flecs 暂不引入）

**数据单向流动**：逻辑库 → 渲染层。渲染层只读，不修改基因与族谱。

## 二、依赖

### 2.1 已接入的第三方逻辑库（`third-lib/`）

| 库 | CMake 目标 | 提供的接口 |
|---|---|---|
| `libgene-lib.a` + `gene_lib.h` | `gene_lib` | `gene_lib_seed/generate`（随机生成）、`gene_lib_breed`（繁育）、`gene_lib_describe`（文本描述）、`gene_lib_phenotype`（机器可读表型） |
| `librelationship.a` + `relationship.h` | `relationship` | `Pedigree / Litter / Cat` 数据结构，`cat_add / cat_children / cat_ancestors / cat_generation_all` 等查询，`pedigree_save / load` |

约定：`GeneLibGene.value` 是**不透明基因载体**，渲染层不解析其位含义，只通过 `gene_lib_phenotype` 取表型。
`gene_lib` 内部持有全局随机流，必须单线程串行调用。

### 2.2 渲染相关依赖

| 库 | 作用 |
|---|---|
| SDL2 | 窗口、事件、OpenGL 上下文 |
| glad | OpenGL 4.5 core 函数加载 |
| cglm | 矩阵 / 向量 / 四元数 |
| cgltf | glTF 2.0 解析（网格、骨骼、动画、材质） |
| stb_image | PNG/JPG 贴图解码 |
| Dear ImGui | 调试面板、基因/表型查看、资产热重载 |
| cJSON | 读取资产配置 json |

### 2.3 目录与构建

```
cat-house/
├─ include/       本项目对外头文件（model.h / renderer.h / phenotype.h）
├─ src/           渲染主程序（入口 main.c）        → bin/cat-house.exe
├─ test/          CuTest 单元测试入口               → bin/cat-house-test.exe
├─ third-lib/     第三方库，一个库一个目录
└─ doc/           设计文档
```

`third-lib/` 内每个库自成一目录，目录内统一为 `include/`（头文件）、`src/`（需编译的源码）、`lib/`（预编译库）、`CMakeLists.txt`：

```
third-lib/
├─ sdl2/          源码编译静态库（与主程序同一套 UCRT 运行时）
├─ glad/          glad.c → glad      （OpenGL 4.5 core）
├─ cglm/          header-only        （cglm     INTERFACE 目标）
├─ cgltf/         cgltf_impl.c       （cgltf）
├─ stb/           stb_image_impl.c   （stb）
├─ cjson/         cJSON.c            （cjson）
├─ imgui/         源码编译静态库      （imgui，C++）
├─ gene-lib/      lib/libgene-lib.a + include/gene_lib.h        （gene_lib）
└─ relationship/  lib/librelationship.a + include/relationship.h（relationship）
```

- `third-lib/CMakeLists.txt` 只负责 `add_subdirectory` 各库；预编译库用 `add_library(... STATIC IMPORTED GLOBAL)` 暴露 `gene_lib`、`relationship`。
- `src` 产出可执行程序，链接 `gene_lib`、`relationship` 与渲染相关库；`-Wall -Wextra` 只作用于本项目代码。
- `test` 直接编译 `src/*.c`（排除 `main.c`）并链接同一批库，无需额外造库。
- Windows 下主程序定义 `SDL_MAIN_HANDLED` 并自带 `main`，不依赖 `SDL2main`。

## 三、核心数据流

```
gene_lib_seed / gene_lib_generate（流浪猫）
gene_lib_breed（亲代 → 子代）        ──► GeneLibGene { value }
                                              │
                                              ├─► gene_lib_describe()  ──► 文本（调试面板 / UI 展示）
                                              │
                                              └─► gene_lib_phenotype() ──► GeneLibPhenotype
                                                                             │
relationship：pedigree_init / cat_add / cat_litters … ──► Cat { litter, gene } ┘
                                                                             ▼
                                                                    渲染表现层 Renderer
```

渲染层每只猫只需要三样输入：

1. `GeneLibPhenotype`（外观，由 `gene` 派生，可缓存）
2. 变换（位置、朝向、缩放）；二期再补充动画状态（动画名、播放进度、混合权重）
3. 资产句柄（哪一份 glb / 贴图）

## 四、表型 → 渲染映射

| 表型字段 | 渲染用途 |
|---|---|
| `sex` / `alive` | 体型比例微调；`alive == 0` 不生成实例 |
| `base_color` | 调色板索引 → albedo 基色 |
| `orange / agouti / pattern / brown / dilution / silver / colorpoint / white` | 决定最终毛色与是否存在花纹，是 `pattern_layout` 的成因，渲染层只消费结果 |
| `pattern_layout` | 花纹指令：元球区域（白斑/玳瑁）、贝塞尔条纹（虎斑）、渐变（重点色）、噪声（银化/烟色）。按 `layers[0..count-1]` 顺序叠加 |
| `ear_shape` + `ear_severity` | 立耳/折耳/卷耳：耳朵骨骼旋转 + 顶点混合权重 |
| `eye_color` | 眼部材质参数 |
| `hair_length` / `hair_texture` | 毛发 shader 参数：短毛/长毛、正常/卷毛/无毛 |
| `leg_length` | 腿骨缩放（矮脚） |
| `tail_form` | 尾骨长度/形态 |

一期落地范围：只消费 `base_color`、`pattern_layout`，可选 `eye_color`；`ear_shape / leg_length / tail_form / hair_*` 等形态类字段先解析、不呈现，等二期模型与骨骼完善后再接入。

实现优先级建议：

1. 先做 `base_color` 调色板 + `pattern_layout` 烘焙到一张花纹贴图（CPU 生成 → 上传 GPU）；
2. 静态白模阶段不做形态变化；需要区分品种时，最多做整体缩放，不碰骨骼；
3. `eye_color` 用材质参数近似；`hair_*` 留到二期。

## 五、渲染子系统

| 模块 | 职责 |
|---|---|
| 平台层 | SDL2 窗口/事件、OpenGL 上下文 |
| 资源管理器 | 加载 glb / 贴图 / 配置，引用计数，多只猫共享同一份资产 |
| 静态网格 | cgltf 读取节点、网格、材质，按节点层级拼出世界矩阵后直接绘制（一期，无蒙皮） |
| 骨骼动画（二期） | cgltf 动画采样（step/linear/cubic）→ 局部矩阵 → 骨骼空间矩阵 → 皮肤矩阵；动画名固定 `idle / sleep / pet / walk` |
| 表现层 | 消费 `GeneLibPhenotype`，生成材质参数与花纹贴图，缓存到实例上 |
| 绘制层 | 透视相机（可调 FOV）、深度测试、`glDrawArraysInstanced` 实例化绘制、固定方向光、暂不做阴影 |
| 调试层 | ImGui：按猫展示 `gene_lib_describe` 文本与表型字段、切换表型、热重载资产（动画控制二期再加） |

关键简化：场景很小、模型数量有限，一期只有静态姿势；不做阴影、后处理、视锥剔除与 LOD，也不需要动画状态机。

## 六、资产规范

- 模型（一期）：glTF 2.0 Binary `.glb`，**静态站立的猫咪网格即可**，不要求骨骼与动画；
- 动画（二期）：全部放在同一 glb，骨架唯一，名称固定 `idle / sleep / pet / walk`，骨骼命名不使用中文；
- 贴图：PNG，sRGB；眼睛与花纹可用 Alpha；
- 配置：`cat_asset_config.json`，记录资产路径、默认材质、光照、各动画速度、动画混合时长；
- 坐标：统一 Y-up（Blender 导出时设置），C 侧不做多套坐标转换。

静态白模到位前：先用任意占位 glb（一个方块也可以）把「加载 → 表型上色 → 多实例绘制」管线跑通；换白模只替换资产，不改代码接口。

可选：Godot 4 仅作为**离线**资产校验/调参工具（检查骨骼权重、动画断裂、材质参数），产出的参数写进 json；它不参与打包，也不承担任何运行期逻辑。

## 七、里程碑

### M1：基因 → 表型（不依赖模型，先做）

- 在 `test/` 中调用 `gene_lib_seed` + `gene_lib_generate`，再调用 `gene_lib_phenotype` / `gene_lib_describe`；
- 断言：`sex` 合法、`alive` 取值正确、`base_color` 在调色板范围内、`pattern_layout.count <= GENE_LIB_MAX_PATTERN_LAYERS`；
- `src/main.c` 启动时打印若干只猫的描述文本与关键表型字段，作为后续渲染的观察入口。

### M2：窗口 + 静态白模

- SDL2 + glad + cgltf，加载静态站立 glb 并绘制（只走节点层级世界矩阵，不做蒙皮）；
- 透视相机、固定方向光；
- 先硬编码一只猫，验证「文件 → 屏幕」这一段。

### M3：表型驱动外观

- `base_color` 调色板 → albedo 颜色；
- `pattern_layout` 烘焙成花纹贴图（CPU 生成 → 上传 GPU），相同表型共享缓存；
- `eye_color` 用材质参数近似；
- ImGui 里切换表型，肉眼确认同一白模能呈现不同花色。

### M4：多实例 + 族链接入

- 从 `Pedigree` 遍历 `Cat`，`gene → phenotype → 实例`；
- 实例化绘制，验证几十只猫的帧率；
- 用 `cat_generation_all` 生成代际信息，调试面板展示。

### M5：场景展示与打包

- 多只猫在场景中摆放、相机可调（ImGui 控制位置/FOV）；
- 静态链接、资产目录打包、发布宏关闭 ImGui。

### 二期：动画与形态

- 骨骼动画采样、蒙皮、动画混合（`idle / sleep / pet / walk`）；
- `ear_shape / leg_length / tail_form / hair_*` 的形态表现；
- 与游戏逻辑库对接行为状态机；
- 一期所有代码按「资产句柄 + 表型」抽象，二期只补渲染管线，不改调用方。

## 八、风险与规避

| 风险 | 规避 |
|---|---|
| 一期把模型/动画耦合进渲染流程 | 一期只做静态网格；动画相关代码（采样、蒙皮、状态机）全部留到二期，调用方只认资产句柄 |
| 白模内容与预期不符（比例、朝向、材质槽） | 白模到位后先跑 M2 单只验证；比例、朝向、材质槽位写进 `cat_asset_config.json` |
| 表型字段语义理解偏差 | 以 `gene_lib.h` 注释为准；表现层只消费字段，不反推基因位点 |
| 实例多时性能下降 | 材质相同的猫合并批次，实例化绘制；花纹贴图按表型缓存（相同表型共享） |
| （二期）骨骼矩阵写错导致模型扭曲 | 先用 Godot/RenderDoc 对照；把骨骼矩阵写日志比对 |
| （二期）cgltf 动画插值与引擎不一致 | 以 Godot 播放结果为真值，先实现 linear，再补 step/cubic |

## 九、暂缓 / 后续

- **Flecs ECS：暂不引入**。当前猫的数量与系统复杂度用 `Pedigree` + 简单数组即可；若后续出现大量系统编排需求再评估。
- **游戏逻辑库**：未来以静态库形式加入 `third-lib`，与渲染层约定只读快照接口：`(gene, transform, 动画状态, 资产 id)`。
- **存档**：直接复用 `pedigree_save / pedigree_load`，渲染层不参与序列化。
- **基因反查**：渲染层不解析 `GeneLibGene.value`；需要更多外观细节时，优先推动 gene_lib 增加表型字段。
